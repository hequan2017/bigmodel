# 检索评测结果（§7.5）

> 评测集：[eval_set.json](eval_set.json)（20 条，基于演示资料命题，人工确认期望文档）。
> 被测库：#31 AI 教学演示库（4 篇演示文档，每篇 1 片段）。
> 评测工具：`go run ./cmd/evaluate -kb 31 -mode <vector|fulltext|hybrid>`。
> 运行日期：2026-11-15。

## 结果

| 通道 | Top-1 命中 | Top-2 命中 | 指标有效性 |
|---|---|---|---|
| **fulltext**（gse 分词后） | **20/20（100%）** | **20/20（100%）** | **有效**：ts_rank 词项相关性为真实计算，不依赖 Embedding 语义 |
| fulltext（重建前） | 9/20（45%） | 9/20（45%） | 有效，但索引为迁移 011 内置粗糙回填（PG 默认解析器不切中文） |
| vector | 5/20（25%） | 10/20（50%） | 无参考意义：mock 上游所有查询向量相同，排序为噪声 |
| hybrid | 7/20（35%） | 19/20（95%） | 无参考意义：RRF 融合中一路为噪声会拖累有效通道 |

## 结论（如实记录）

1. **全文通道已是真实有效的检索指标**：gse 中文分词 + tsvector/ts_rank 在演示语料上
   Top-1 100%。重建索引前后对比（45% → 100%）同时量化了分词质量对检索的影响。
2. **mock 向量是噪声，会拖累 RRF 融合**：hybrid Top-1（35%）显著低于纯全文（100%）。
   因此应用配置新增 `retrieval_mode` 旋钮——Embedding 上游尚为 mock 时建议固定
   `fulltext`，接入真实 Embedding 后复测三通道再选择默认。
3. **运维注意**：迁移 011 之前创建的语料，其 fts 为内置粗糙回填，升级后需对每个
   知识库执行一次 `POST /api/kb/{id}/reindex`（不重新向量化，仅按分词器重建索引）。
   迁移 011 之后新处理的文档由 worker 直接写入分词索引，无需重建。

### 暴露的真实问题（如实记录，待改进）

1. **ts_rank 无 IDF 加权**：命中多个常见词的片段压过命中稀有关键词的片段。
   实测："越权访问返回什么状态码"——含"越权统一 404 防枚举"的片段（最相关）
   得分 0.0122，被含"访问/状态"等常见词的片段（0.0287）压过。
2. **表格类内容被切分拆散、章节归属漂移**：API.md 错误码表格被 600 字符切分
   拆到多个片段，"404 越权"行归属到 heading="页面（同源托管）"的片段；
   "revision_conflict"行不在"错误码"片段中——表格行与章节标题错位。
3. **相邻章节共享词汇导致章节错位**：6.2/6.3（状态）、7.3/7.4（候选）、
   DELIVERY 三/四章——文档命中正确但引用片段落在相邻章节。
4. fts 已并入标题词（本轮改进，worker 与 reindex 一致），演示库基准不受影响
   （保持 Top-1 100%）。

改进方向：表格感知切分、ts_rank_cd/长度归一化、IDF 加权或 Rerank 精排
（§7.4 第 5 步，需真实 Rerank 上游）。
